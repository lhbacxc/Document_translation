# 环境准备与依赖说明

本项目使用**统一的 Python 虚拟环境**，同时支持翻译脚本（`python-docx`）和 AI 检测 skill（`spacy` 等）。

---

## 自动配置流程（推荐）

首次使用时，运行环境配置脚本：

```bash
# 交互式模式（手动运行）
python setup_env.py

# 非交互式模式（AI 助手自动化执行）
python setup_env.py --non-interactive --env-type conda --env-name doc_translation
python setup_env.py --non-interactive --env-type venv --env-name .venv_paper_detection
```

> **使用 AI 助手时的工作流程**：
>
> - AI 助手会先**向你询问环境配置选项**（使用 Conda 还是 venv、环境名称等）
> - 然后使用**非交互式模式**自动运行配置脚本，无需你手动打开终端
> - 脚本支持 `--non-interactive` 参数，允许通过命令行参数指定所有配置选项
> - 这样 AI 助手可以在获取你的配置意图后，直接执行完整的环境配置流程

脚本会自动检测你的环境并引导配置：

1. **有 Conda**

   - 询问虚拟环境名称（默认 `doc_translation`）
   - 自动创建环境：`conda create -n <环境名> python=3.11 -y`
   - 自动安装当前依赖：`pip install -r requirements.txt`
   - 生成配置文件 `.project_env.json` 记录环境信息
2. **无 Conda 但有 Python 3.11+**

   - 询问是否创建 venv（推荐使用 `.venv_paper_detection/`）
   - 自动创建环境：`python -m venv .venv_paper_detection`
   - 自动安装当前依赖
   - 生成配置文件
3. **Python < 3.11**

   - 询问是否升级 Python
   - 提供升级指南（不会擅自操作）
   - 升级后重新运行脚本
4. **无 Python**

   - 提供 Python 安装指南
   - 退出配置流程

> **重要提示**：
>
> - 配置完成后，`.project_env.json` 会记录环境信息，后续无需重复配置
> - 若通过 CLI 工具、脚本或 AI 助手自动化执行本项目，**禁止在程序中使用 `conda activate` 切换环境**
> - 自动化调用脚本时，**必须使用目标环境的 Python 绝对路径**；推荐从 `.project_env.json` 中读取 `python_path`
> - 首次运行 `/translation-paper-detection` skill 时，选择已创建的虚拟环境，skill 会自动安装其所需的额外依赖（spacy, numpy, pandas 等）
> - skill 会生成自己的 `.env_status.json` 记录环境，后续运行直接使用

## 自动化调用的重要约定

本机已安装 Miniconda，但在 CLI 工具或程序的**非交互式调用**里，`conda activate` 可能无法真正切换到目标环境，而是回退到 `base` 环境。因此：

1. **禁止**在脚本、批处理、AI 助手自动化流程中使用 `conda activate <环境名>; python xxx.py` 这种写法。
2. **必须**直接使用目标环境的 Python 绝对路径运行脚本。
3. 推荐把 `.project_env.json` 作为事实来源，优先读取其中的 `python_path` 字段；若只有 `env_path`，可自行拼出解释器路径：
   - Windows + Conda：`<env_path>\\python.exe`
   - Windows + venv：`<env_path>\\Scripts\\python.exe`
   - macOS / Linux + Conda 或 venv：`<env_path>/bin/python`

示例：

```bash
# 错误示例：程序中不要这样写
conda activate doc_translation
python extract_text.py input/你的论文.docx

# 正确示例：直接调用目标解释器
D:\Software\Miniconda\envs\doc_translation\python.exe extract_text.py input/你的论文.docx
```

> 说明：如果你是**手动打开终端**做一次性排查，交互式 `conda activate` 仍可用于人工验证；但项目文档、自动化脚本和 AI 助手流程一律按“绝对路径调用”执行。

## 手动配置流程（可选）

如果不想使用自动脚本，可以手动配置：

```bash
# === 方式 A：使用 Conda（推荐） ===
# 1. 创建虚拟环境
conda create -n doc_translation python=3.11 -y

# 2. 使用目标解释器安装当前依赖
D:\Software\Miniconda\envs\doc_translation\python.exe -m pip install -r requirements.txt

# 3. 手动创建配置文件（可选）
# 创建 .project_env.json 记录环境信息，建议至少包含 env_type、env_name、env_path、python_path


# === 方式 B：使用 venv ===
# 1. 创建虚拟环境
python -m venv .venv_paper_detection

# 2. 使用目标解释器安装当前依赖
.\.venv_paper_detection\Scripts\python.exe -m pip install -r requirements.txt
```

## 虚拟环境与依赖详解

### 环境配置流程

1. **项目初始化**（首次使用）

   - 运行 `python setup_env.py` 自动配置环境
   - 脚本会询问环境类型（Conda/venv）和环境名称
   - 自动安装当前依赖（仅 `python-docx`）
   - 生成 `.project_env.json` 记录环境信息（建议包含 `env_path` 与 `python_path`）
2. **skill 依赖安装**（首次使用 `/translation-paper-detection` 时）

   - skill 会检测并询问是否使用已创建的虚拟环境
   - 选择项目环境后，skill 自动安装其所需依赖（`spacy`, `textstat`, `numpy`, `pandas`, `tqdm`）
   - skill 生成 `.env_status.json` 记录环境配置
   - 后续运行 skill 直接使用记录的环境

### 依赖分层

| 阶段           | 依赖                                                                               | 安装时机                            |
| -------------- | ---------------------------------------------------------------------------------- | ----------------------------------- |
| 项目初始化     | `python-docx`                                                                    | `setup_env.py` 自动安装           |
| skill 首次使用 | `spacy`, `textstat`, `numpy`, `pandas`, `tqdm` + `en_core_web_sm` 模型 | `/translation-paper-detection` skill 自动安装 |

### 环境验证

获取到目标环境的 Python 绝对路径后，可以直接验证依赖是否正确安装：

```bash
# 先确定目标解释器路径
# Windows + Conda:
D:\Software\Miniconda\envs\doc_translation\python.exe -c "import docx; print(f'python-docx {docx.__version__}')"

# 验证检测依赖（首次使用 skill 后）
D:\Software\Miniconda\envs\doc_translation\python.exe -c "import spacy; nlp = spacy.load('en_core_web_sm'); print(f'spacy {spacy.__version__}, model loaded')"
```
